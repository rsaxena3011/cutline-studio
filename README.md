# Cutline Studio

A continuity checker for video producers, built for the Meta Global AI Developer Hackathon (Cerebral Valley, November 2026).

Give it two takes of the same scene, the script or brief for that scene, and the object you care about. Cutline Studio compares the takes, flags where they disagree, and shows the exact frame behind every flag, with its frame time. A human editor accepts or rejects each flag. Nothing is auto-fixed, and nothing is exported without the editor.

## Why

Generating shots is fast now. Checking them is still slow, manual work: a presenter's jacket changes colour between takes, a client logo comes back cropped, a prop vanishes, and someone catches it frame by frame, or nobody does. The generator should not grade its own homework, and neither should a checker that cannot show its evidence. Cutline Studio's standing rule: no flag without evidence, and an uncertain check is raised to the human, never passed silently.

## How it works

1. **Ledger (Muse Wonder).** Wonder reads the script or brief for a scene, and each take of it, and writes a structured scene ledger: objects on set, wardrobe, props, screen positions, and the beats the brief calls for. The ledger is a fixed schema (see `src/ledger/scene_ledger.schema.json`), because the rest of the pipeline diffs two takes field by field. A chat answer cannot be diffed. A ledger can.
2. **Segment (SAM 3.1).** SAM 3.1 segments the tracked object in stills and in frames sampled from short clips. The mask is the evidence surface: every flag shows the mask on the frame it came from. Clips are checked frame by frame, each sampled frame judged as a still. Cutline Studio does not claim tracking across frames.
3. **Compare (deterministic code).** Plain code diffs the two ledgers and the mask measurements and catches the provable differences: an object present in one take and missing in the other, a mask that moved or changed size.
4. **Judge (Muse Spark).** Spark takes what measurement cannot settle, for example whether the jacket in take two is the same jacket in different light or a different jacket, and must cite the ledger lines and frames behind its call.
5. **Review (human).** The editor works the flag list with two or three voice commands (accept, reject, next flag) and makes every final call.
6. **Repair (Muse Image, narrow).** On request, a flagged frame goes out as a targeted edit on an uploaded still, and the result re-enters the same checks before the editor sees a pass. Muse Image is never the source of the takes being checked.

## Scope, stated plainly

- Stills are the primary path. Short clips are supported as frame-sampled stills checks only; no cross-frame tracking is claimed.
- Generation and repair are limited to stills. The takes being checked are uploaded, never generated by the tool.
- No accounts, no cloud libraries, no collaboration, no auto-edit export, no fine-tuning.
- Demo mode runs on fixtures (cached ledgers, masks, and judgments) so a review never depends on a live API call. Live mode is one toggle.

## Setup

1. Clone the repository. Python 3.10 or newer; dependencies are Pillow, numpy, and requests (plus meta-sam-parser for live mode).
2. Copy `.env.example` to `.env` and fill in what you have. Live mode needs a Meta Model API key (`META_API_KEY`, also accepted as `META_MODEL_API_KEY`). No key is ever committed.
3. Without a key, the app runs in fixture mode against the bundles in `fixtures/`, which is the default demo path.

## Run the v1 slice (stills QC flow)

The v1 slice is the full stills loop: image in, segmentation, deterministic comparison, verdict out, with evidence.

```
# One still: segment the named object and return a verdict.
python3 -m src.cli check-still --image fixtures/studio_desk/take_a.png \
    --object "brass lamp" --color 212,160,23 --tolerance 50

# Two takes from a fixture bundle: compare and judge.
python3 -m src.cli compare --bundle fixtures/studio_desk \
    --object "brass lamp" --out-dir build/last-run
python3 -m src.cli compare --bundle fixtures/studio_desk \
    --object "presenter jacket" --judge jacket_identity

# Tests (16, standard library unittest):
python3 -m unittest discover -s tests -t .
```

The `studio_desk` bundle (generated by `fixtures/make_fixture_bundle.py`) plants the three cases the demo is built on: the brass lamp missing in take two (BLOCK, with the ledger lines as evidence), the sponsor logo drifted to the frame edge (REVIEW, a cropping warning, never proof), and the presenter's jacket in a lighter shade (a Muse Spark judgment case, settled only with citations to the ledgers and frames). Add `--interactive` to a compare run for the editor's accept / reject pass. Live mode is `--mode live` on either command once a key is in `.env`; it calls SAM 3.1 through the Meta Model API for stills. Fixture mode remains the default, so a review never depends on a live call.
